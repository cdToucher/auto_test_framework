ATK SPA Shop Dogfood 全流程

本文记录一个真实可复跑的本地示例：在 examples/ 中提供单页面商城应用，用当前 ATK 项目完成 API 自动化、AI 浏览器 E2E、记录、报告和 gate。

关键边界：当前 atk run 原生执行 api: 步骤；ui: 场景作为 E2E 意图存在，由 AI 在 TUI/CLI 中驱动浏览器实际执行，再通过 atk record --from-json 写入同一份 run 记录。

1. 示例目标

文件作用
examples/spa_shop.py本地单页面商城，被测系统。包含登录、优惠券、下单、订单查询。
scenarios/spashop/checkout_success.yamlAPI 正向链路：登录、使用 SAVE10 下单、按订单号查询。
scenarios/spashop/coupon_reuse_rejected.yamlAPI 负向链路：同一会话重复使用优惠券返回 409。
scenarios/spashop/ui_checkout_flow.yamlE2E 意图：页面登录、下单、查询订单。
tests/test_spa_shop.py保护示例服务的核心业务行为，避免 dogfood 目标自身漂移。

2. 人和 AI 怎么协作

人： 1. 提供需求和环境，比如“验证 SPA 商城下单与优惠券” 2. 审查 AI 生成或修改的 expect 是否符合业务 3. 对最终 run 做 approve/reject AI： 1. 读取代码、场景、config，确认接口和页面事实 2. 编写或复用 API 场景，确保 expect 覆盖关键业务字段 3. 运行 atk validate 和 atk run 4. 用浏览器执行 E2E 意图 5. 用 atk record --from-json 写入结果与证据 6. 生成 report，执行 gate，给出结论 ATK： 1. 保存 run 记录 2. 自动执行 API/YAML 场景 3. 生成 HTML/JUnit 报告 4. gate 检查变更一致性、失败、未定性事项

3. 复跑命令

启动被测 SPA

.venv/bin/python -m examples.spa_shop

服务地址：

http://127.0.0.1:8777/

校验场景库

.venv/bin/python -m atk validate

期望结果：所有 YAML 场景通过解析、字段校验和重名检查。

建立 run 记录

.venv/bin/python -m atk plan \
  --base HEAD \
  --head HEAD \
  --title spashop-local-full-flow \
  --format json

本地未提交 dogfood 可使用 HEAD -> HEAD 建立记录；真实 PR/MR 中应传实际 base/head，让 ATK 按 diff 命中模块和复用场景。

执行 API 自动化

.venv/bin/python -m atk run \
  --env spashop \
  --module spashop \
  --tags api \
  --record-to <run_id> \
  --junit reports/spashop-junit.xml

期望结果：两个 API 场景全部通过。

执行 E2E 并结构化记录

AI 在 TUI/CLI 中打开浏览器，完成以下动作：

  1. 打开 http://127.0.0.1:8777/。
  2. 使用 qa/secret123 登录。
  3. 选择 ATK Starter Kit，数量 1，优惠券 SAVE10。
  4. 提交订单，并查询刚生成的订单号。
  5. 断言页面显示已登录、订单状态为待支付、商品正确、应付金额为 89。

AI 完成浏览器验证后生成结果 JSON：

{
  "title": "AI E2E: SPA 商城页面登录下单查询",
  "status": "pass",
  "note": "浏览器完成登录、下单、查询。页面状态：已登录 qa；订单 SOxxxx；状态待支付；商品 ATK Starter Kit；应付 ¥89。",
  "evidence_files": ["/tmp/spashop-ui.png"]
}

然后回填到 run：

.venv/bin/python -m atk record <run_id> --from-json /tmp/spashop-ui-result.json

开发或 AI 代表本地 dogfood 确认

.venv/bin/python -m atk review <run_id> \
  --by codex \
  --verdict approve \
  --note "dogfood: API 自动化通过，AI 浏览器 E2E 已归档"

生成报告并门禁

.venv/bin/python -m atk report <run_id>
.venv/bin/python -m atk gate <run_id> --format json

5. dogfood 暴露出的框架改进

已修复：API 请求 path/header/body 原本支持变量替换，但 expect.value 不支持。AI 很自然会写出 data.user: "${username}" 这种断言，因此已补齐断言值同口径变量替换，并添加回归测试。

6. 后续建议

  • 让 atk plan 支持 working tree diff，便于本地未提交改动也能准确命中模块。
  • 为 ui: 场景定义更稳定的结构化字段，例如入口 URL、选择器线索、关键断言、截图要求。
  • 后续接入内置 UI executor 时，沿用当前 record --from-json 的结果结构，避免破坏 TUI/CLI 协作模式。
