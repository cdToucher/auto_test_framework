## 1. 背景与目标

### 问题

1. **角色分工失效**：AI 开发能力扩张打破了原有 Dev/QA 分工，AI 能做测试但核心能力（业务判断、质量定性）仍有门槛，产出不稳定。
2. **DevOps 测试环节缺失**：有 CI 无测试，大量功能依赖人工点击和冒烟测试。

### 现状

- 被测系统：Vue 前端 + Java/Spring 后端
- 团队：有专职 QA（跟不上 AI 开发节奏），开发者以 Agent CLI（Claude Code / OpenCode 类）为主要开发工具
- CI：已具备构建流水线，无测试阶段

### 目标

交付"工具 + 流程"双轨方案：

1. **工具轨**：可运行的自动化测试框架 `atk`，替代人工冒烟，接入 CI 门禁
2. **流程轨**：AI 协作角色规范，明确人机能力边界与质量门禁规则

成功标准：

- 合并前无需任何人手工点击冒烟
- QA 日常工作对象从"点页面/写代码"变为"审中文场景 + 定性失败报告"
- 回归集可重复执行且随迭代自动维护

## 2. 总体架构：双层设计

```
触发入口：本地 CLI 手动 │ 夜间定时批量 │ 周级全量
        │                          │
        ▼                          ▼
┌─────────────────┐      ┌──────────────────┐
│  即时层（冒烟）    │      │  沉淀层（回归）     │
│  diff→AI生成意图  │      │  YAML 场景库回放    │
│  →实测当前环境    │      │  （固化脚本确定性跑）│
│  不落库          │      │                  │
└────────┬────────┘      └────────┬─────────┘
         ▼                        ▼
┌─────────────────────────────────────┐
│            共享执行器                 │
│   API 执行器(httpx) │ UI 执行器      │
│                    (ego-browser)   │
└──────────────────┬──────────────────┘
                   ▼
        统一报告（截图+断言证据）
```

### 两层职责

| 层 | 解决什么 | 资产形态 |
|---|---|---|
| 即时层 | 变更后快速反馈，探索新功能路径 | 无资产，即跑即弃 |
| 沉淀层 | 可重复回归、CI 门禁 | YAML 场景（唯一人工资产）+ 固化脚本（编译产物） |

### 核心组件（5 个）

| 组件 | 职责 |
|---|---|
| `diff-analyzer` | 解析 git diff，结合调用链/路由表识别受影响的接口与页面 |
| `planner` | 将改动翻译为测试意图（即时层）或场景草稿（入库候选）；优先复用场景库已有场景 |
| `api-executor` | httpx 直调接口 + schema/业务断言 |
| `ui-executor` | ego-browser 按步骤操作浏览器，每步截图取证；失败自动重试一次排除环境抖动 |
| `reporter` | 统一报告：结论（通过/失败/疑似失败）、证据链、门禁凭证 |

## 3. YAML 场景格式

沉淀层的唯一人工维护资产。示例：

```yaml
# scenarios/order/create_order.yaml
scenario: 下单主流程
module: order            # 模块归属，便于按模块回归
priority: P0             # P0=门禁必跑 / P1=夜间回归 / P2=周级全量
tags: [smoke, order]
env: staging             # 执行环境
steps:
  - api:                       # 接口步骤：结构化字段，直接模板编译为确定性脚本
      call: POST /api/orders
      body: { skuId: "${test_sku}", qty: 1 }
      expect: { status: 200, "data.orderNo": not_null }
  - ui:                        # UI 步骤：自然语言描述，固化时由 AI 翻译为 Playwright 选择器
      action: 用订单号搜索订单列表
      expect: 列表出现一条状态为"待支付"的记录，金额与下单金额一致
```

设计要点：

1. **API 步骤结构化**：不依赖 AI 即可回放
2. **UI 步骤自然语言**：QA 零代码负担
3. **expect 断言是场景灵魂**：QA 评审的核心对象就是断言的业务正确性
4. **`${变量}` 占位**：测试数据从 fixtures 注入，支持多环境切换
5. **priority 三级**：直接映射三档执行时机（门禁/夜间/周级）

## 4. 即时层工作流

```
触发（本地 atk smoke 或夜间批量）
  1. diff-analyzer：git diff + 调用链/路由表 → 影响面报告
  2. planner：影响面 + 场景库检索（优先复用已有 YAML 场景）
     无覆盖处生成新测试意图（不落库）→ 执行计划
  3. 执行：API 检查（httpx 断言）+ UI 流程（ego-browser 实操+截图，
     失败自动重试一次）
  4. reporter：
     - 结论：通过 / 失败 / 疑似失败（需人工定性）
     - 证据链：影响面 + 截图 + 断言结果 + 失败根因猜测
     - 通过 → 报告哈希挂到 MR，作为合并门禁凭证
     - 高价值新意图 → 提示 QA"建议沉淀"，AI 一键转 YAML 草稿
```

关键决策：

| 决策 | 理由 |
|---|---|
| 先复用场景库再新生成 | 避免重复造轮子；即时层持续"喂养"沉淀层 |
| 引入"疑似失败"状态 | AI 判定不确定时不硬判，防幻觉误杀 |
| 报告哈希做门禁凭证 | 门禁校验"该变更存在通过的报告"，而非强制现跑，兼容"push 不立即测"诉求 |

## 5. 沉淀层固化与自修复

### 固化流水线（YAML → 确定性脚本）

```
QA 提交 YAML
  → API 步骤：模板直接编译（不走 AI）
  → UI 步骤：AI 翻译为 Playwright(Python) 脚本
  → 自动试跑验证：通过才算固化成功
  → 失败带错误信息重译（最多 3 次），仍失败退回 QA 改 YAML
```

- 固化产物统一放 `generated/`，标记禁止手改；人只管 YAML
- UI 改版导致脚本失效时，从 YAML 重新固化即可，YAML 通常无需改动

### 自修复流程（夜间回归脚本失败时）

| 失败类型 | 判定方式 | 处理 |
|---|---|---|
| 选择器失效 | 元素找不到/超时，但页面功能正常 | AI 读新页面结构重新翻译该步骤，自动提修复 PR |
| 业务断言失败 | 断言值不符 | 不修——疑似 bug，出报告交 QA 定性 |

每次自修复生成 diff 留痕，QA 每周抽查。

## 6. 触发机制与门禁

| 档位 | 触发方式 | 内容 |
|---|---|---|
| 手动 | 开发者本地 `atk smoke` | 本次变更即时层冒烟 |
| 夜间 | CI 定时 22:00 | 当日全部变更批量冒烟 + P1 回归 + 自修复 |
| 周级 | 每周五晚 | 全量 P0+P1+P2 |
| 门禁 | MR 合并前 / 发布前 | bot 校验 MR 挂有通过的冒烟报告哈希；发布需夜间全量通过且无未定性失败 |

## 7. 角色与流程规范（流程轨）

| 角色 | 现状 | 目标分工 |
|---|---|---|
| Dev | 写代码 + 凭感觉自测 | 对影响面报告负责；触发即时层并修到冒烟通过 |
| QA | 手工点测，追不上节奏 | 审 YAML 场景（业务正确性）；定性失败报告；维护测试数据 fixtures |
| AI Agent | 无定位 | diff 分析、场景草稿生成、脚本固化、自修复——所有产出均为草稿性质 |

能力边界三原则：

1. AI 产出一律是草稿，人只评审决策，不写底层实现
2. 确定性判断交给编译产物（固化脚本），AI 不直接判定合并
3. AI 不确定的结论标"疑似"，强制人工定性，禁止静默通过

## 8. 目录结构

```
auto_test_framework/
├── atk/                  # 框架核心包
│   ├── cli.py            # typer 入口
│   ├── diff_analyzer/    # 变更影响面分析
│   ├── planner/          # 测试计划生成
│   ├── executors/        # api_executor.py / ui_executor.py
│   ├── solidify/         # YAML→Playwright 固化 + 自修复
│   ├── reporter/
│   └── store/            # 场景库读写
├── scenarios/            # YAML 场景库（QA 维护）
├── generated/            # 固化脚本产物（禁手改）
├── fixtures/             # 测试数据
├── config/environments.yaml
└── reports/              # 报告归档（gitignore）
```

## 11. 错误处理原则

- 环境类错误（服务不可达、登录失效）：标记"环境异常"，不计入用例结果，提示检查环境
- 即时层 UI 步骤失败自动重试一次，仍失败才报失败
- AI 相关步骤均设最大重试上限（3 次），超限退回人工
- 所有报告必须可追溯：记录 diff 版本、场景版本、环境信息
